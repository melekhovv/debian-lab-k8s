# Security considerations

[README](../README.md)

Это описание границ доверия и известных ограничений по исходникам, а не полный security scan, pentest или подтверждение отсутствия уязвимостей.

## Текущая модель

- Webtop рассчитан на локальную лабораторию без настроенной аутентификации рабочего стола; исходный README указывает passwordless sudo. Не считать браузерный рабочий стол безопасным для общего доступа.
- Сервер запускается с `privileged: true`: компрометация сервера способна затронуть ноду Minikube. Клиенты имеют `NET_ADMIN` в контейнере.
- Port-forward по умолчанию слушает `127.0.0.1`. Доступ с того же Windows-хоста остаётся в границах доверия. Не менять bind на `0.0.0.0` для демонстрации портфолио.
- ClusterIP даёт внутреннюю точку доступа; он не является аутентификацией и не закрывает сервис от других участников кластера. В текущих YAML нет NetworkPolicy или отдельной политики RBAC для лаборатории.
- Скрипты запускаются с правами управления Docker/Kubernetes, входят в ноду и меняют её маршруты, sysctl и iptables. Они рассчитаны на выделенную ноду, не на общий кластер.
- `lab.config.ps1` dot-source исполняет PowerShell-код. Не принимать чужой конфиг как безобидный набор данных.

## Сеть и хранение

Policy routing управляет путём учебного трафика, но не заменяет firewall. Отключение rp_filter и NOTRACK ослабляет проверки/учёт для затронутого трафика. Нужна отдельная оценка до расширения стенда.

Backup writable layer может содержать SSH-ключи, shell history, учётные данные приложений и БД. `.gitignore` исключает локальный конфиг, `.env` и `backups/`, но не предотвращает публикацию через другие пути или уже отслеживаемые файлы. Копии в ноде и на том же компьютере не защищают от потери всего компьютера. Шифрование, off-host хранение и проверка целостности в скриптах не реализованы.

## Legacy

В `legacy/` VNC-пароль передаётся через окружение/Secret; Kubernetes Secret не равен шифрованию по умолчанию. Compose публикует 5901 и 6080 без ограничения loopback; старые YAML содержат NodePort и Ingress. Они не используются текущим запуском и требуют отдельного рассмотрения перед активацией.

## Безопасная демонстрация

Для портфолио используйте обезличенные снимки и вывод команд. Не выкладывайте `lab.config.ps1`, архивы, kubeconfig, Secret, пароли, дампы БД, токены или полные истории shell. Проверяйте скриншоты на адреса, имена пользователей и данные в открытых вкладках.

Рекомендации для отдельного этапа: аутентификация GUI, оценка минимальных привилегий, выделенный профиль/context, явное владение сетевыми правилами, off-host зашифрованные backup и тест восстановления. Эти меры не заявлены как выполненные. Изменения могут сломать DinD, маршрутизацию, GUI или recovery; сначала согласовать область, проверить на копии и определить возврат.
