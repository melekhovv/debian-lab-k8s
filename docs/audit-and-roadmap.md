## Этап 4 — отдельные изменения реализации

Кандидаты, не выполненные в этом наборе документации:

1. Проверки ожидаемых context/profile/node и runtime-утилит до изменений.
2. Проверка stop/start БД и обработки файловых ошибок backup; обязательный recovery-тест.
3. Явное владение сетевыми правилами, проверка конфликтов table 100/pref 1000, исправление выбора Pod IP.
4. Воспроизводимая настройка Linux services и обезличенный экспорт Zabbix.
5. Оценка аутентификации GUI, минимальных привилегий, probes, PVC и off-host backup.

Каждое предложение оформлять отдельно: проблема → diff → влияние → проверка на копии → backup → окно изменений → критерий возврата. Смена образа и PVC меняют recovery; возврат YAML не восстанавливает потерянные данные. Без испытания безопасный rollback не обещать.

## Критерий готовности портфолио

README честно описывает границы; схемы совпадают с исходниками; каждый заявленный выполненный кейс связан с реальными доказательствами. Пока runtime-артефактов нет, это портфолио реализации и инженерных решений, а не отчёт о подтверждённой эксплуатации.
