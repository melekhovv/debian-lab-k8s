# Кейс: маршрутизация между учебными подсетями

[README](../../README.md) · [Топология](../network-topology.md)

**Статус:** проверено на стенде 14 ноября 2026 года: шесть TCP-направлений, forwarding counters и вход/выход пакетов на сервере с уменьшением TTL. [Протокол и JSON](../evidence/2026-11-14-runtime.md).

## Задача и решение

Направить межклиентский трафик через Debian-сервер в контейнерной среде, где нода сама может доставить пакеты между Pod. В `start-debian.ps1` реализованы дополнительные IPv4-адреса, proxy ARP, policy routing на ноде и forwarding сервера.

Источники: [LabSubnets и участники](../../lab-common.ps1), [сетевой блок и self-test](../../start-debian.ps1). Наличие кода подтверждает проектное решение, а не прохождение проверки.

## План проверки

Сначала собрать read-only данные: Pod UID/IP, адреса и маршруты клиентов/сервера, правила и таблицу `100`, host routes и `LAB-NOTRACK` на ноде. Примеры команд — в [troubleshooting](../troubleshooting.md).

Затем в согласованное время выполнить ограниченные сетевые пробы:

| Направление | Ответ | Путь через сервер | Доказательство |
|---|---|---|---|
| client1 → client2 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |
| client1 → client3 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |
| client2 → client1 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |
| client2 → client3 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |
| client3 → client1 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |
| client3 → client2 | Ответ получен | Вход TTL 63 → выход TTL 62 | [Протокол](../evidence/2026-11-14-runtime.md) |

Для каждой пробы записать команду, адреса, время и результат. Если инструменты уже установлены, сопоставить traceroute или ограниченный захват только тестового трафика с изменением `ForwDatagrams` сервера. Захват требует прав и может содержать данные; установку инструментов и захват согласовать отдельно.

## Критерий приёмки

Все шесть направлений получают ожидаемый ответ; для каждого есть независимое подтверждение прохождения сервера. Простого ping или роста общего счётчика при фоновом трафике недостаточно для строгого доказательства пути. Недоступность ICMP сама по себе не доказывает ошибку routing: учитывать протокол и фильтрацию.

## Формулировка для портфолио сейчас

«Реализована и проверена маршрутизация между тремя учебными подсетями через Debian-сервер. Для шести направлений получены сетевые ответы и зафиксированы вход/выход пакетов на сервере с уменьшением TTL. Ограничения и артефакты опубликованы».

Проверка отказа сервера или пересоздания Pod — потенциально прерывающий работу этап. Он не выполнен и требует отдельного согласования.
