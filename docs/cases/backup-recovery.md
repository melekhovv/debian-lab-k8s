# Кейс: backup и recovery контейнерного состояния

[README](../../README.md)

**Статус:** механизм реализован; успешное восстановление файлов и БД не подтверждено стендовыми результатами.

## Задача и реализация

Сохранить изменения учебных сред без постоянных томов и импортировать их после потери ноды. `save-state.ps1` находит overlayfs upperdir через containerd, копирует его `rsync -aHAX --numeric-ids`, затем экспортирует архив на Windows. `lab-common.ps1` обрабатывает whiteouts и opaque directories при восстановлении.

| Среда | Копия в ноде | Windows по умолчанию |
|---|---|---|
| Сервер | `/var/backup_desktop` | `backups/desktop.tgz` |
| Клиент 1 | `/var/backup_client1` | `backups/client1.tgz` |
| Клиент 2 | `/var/backup_client2` | `backups/client2.tgz` |
| Клиент 3 | `/var/backup_client3` | `backups/client3.tgz` |

Windows-экспорт использует временный файл и сохраняет предыдущий как `.tgz.prev`. В ноде новая копия сначала пишется в `fs.new`, затем заменяет `fs`. Это последовательность операций с обработкой части ошибок, не транзакционная гарантия против любого сбоя питания или диска.

Источники: [save-state](../../save-state.ps1), [restore helper и исключения](../../lab-common.ps1), [импорт и восстановление](../../start-debian.ps1).

## Порядок сохранения

Запуск save-state меняет состояние: временно останавливает обнаруженные активные `zabbix-server`, `mariadb`, `mysql`, `postgresql`; после копирования пытается запустить их в обратном порядке. Коды остановки и последующего запуска не проверяются. Нельзя гарантировать согласованность БД по одному сообщению об успешном копировании.

Скрипт отказывается сохранять контейнер без `/run/lab-restored`, если не задан `-Force`. Маркер означает прохождение подготовки, а не доказанную прикладную исправность. `-Force` отключает защиту от перезаписи хорошей копии свежим состоянием. `-NoExport` оставляет копию только внутри ноды.

## Что восстанавливается

При отсутствии маркера start ищет `fs` в ноде. Если его нет, импортирует Windows tgz, когда он существует; затем применяет слой к корню живого контейнера. Если копии нет, начинает с чистого состояния. Автоматического выбора `.tgz.prev` или копии по дате нет.

Это слой изменений поверх базового образа, не полный независимый образ системы. Исключаются `/tmp`, `/run`, `/dev`, `/proc`, `/sys`, ряд runtime-файлов и apt cache. Kubernetes-managed файлы и runtime mounts имеют отдельный жизненный цикл. Адреса/маршруты создаются заново, сервисы запускаются по конфигурации. Совместимость копии с другим digest/runtime не подтверждена.

## Read-only проверка существующих копий

Без сохранения, перезапуска или восстановления можно проверить наличие, дату, размер и локальный SHA-256 архивов:

```powershell
Get-ChildItem -LiteralPath .\backups -Filter *.tgz | Select-Object Name,Length,LastWriteTime
Get-ChildItem -LiteralPath .\backups -Filter *.tgz | Get-FileHash -Algorithm SHA256
```

Для нестандартного BackupDir укажите реальный каталог. Хеш позволяет сравнить файл с эталоном; он не доказывает полноту, согласованность или восстанавливаемость данных.

## Испытание восстановления — отдельно согласовать

1. Сохранить неизменяемую копию исходных архивов вне рабочей ноды, проверить место и SHA-256. Записать digest и версии runtime.
2. Выделить изолированную среду на другом тестовом хосте. Скрипты жёстко обращаются к контейнеру `minikube`; второй профиль на том же Docker-хосте не считать безопасно поддержанным.
3. На тестовой среде подготовить контрольные файлы с хешами, права, симлинк и удалённый файл; если есть тестовая БД — контрольную запись. Зафиксировать значения.
4. Сохранить состояние и отдельно проверить остановку/возврат сервисов. Проверить экспорт без публикации секретов.
5. Пересоздать только согласованную тестовую среду, импортировать копию и проверить файлы, whiteouts, права, запись БД и прикладную готовность.
6. Записать время сохранения/восстановления, потери относительно последнего backup и все ошибки. Лишь после этого публиковать измеренные recovery metrics.

| Доказательство | Текущий статус |
|---|---|
| Проверенные Windows-архивы и хеши | Не приложены |
| Протокол восстановления файлов | Не выполнен |
| Проверка контрольной записи БД | Не выполнена |
| Время восстановления | Не измерено |

Не удалять рабочий Minikube и не сбрасывать Docker Desktop ради кейса. Копии на том же компьютере не заменяют off-host backup. Копирование живого слоя не гарантирует согласованность всех приложений.
