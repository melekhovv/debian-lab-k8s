# Кейс: управление Linux services

[README](../../README.md)

**Статус:** логика запуска подтверждена исходниками; установка и фактическая работа сервисов не подтверждены.

## Задача и реализация

После восстановления контейнера запускать необходимые приложения. Списки задаются в локальном конфиге: по умолчанию сервер использует MariaDB, Apache, Zabbix server/agent, клиенты — Zabbix agent.

Скрипт проверяет исполняемый `/etc/init.d/<service>`, затем статус и запуск через `service`. Отсутствующие пакеты пропускаются, не устанавливаются. Это управление init-скриптами внутри контейнера, а не подтверждённая эксплуатация systemd-хоста. Обёртка `hostnamectl` также не доказывает наличие systemd.

Источники: [списки сервисов](../../lab.config.example.ps1), [цикл запуска и hostname](../../start-debian.ps1).

## План проверки

1. Зафиксировать `/etc/os-release`, версии пакетов и наличие init-скриптов. Сначала только чтение, без установки/обновления.
2. Для каждого установленного сервиса собрать статус, сведения о процессе, слушающих портах и относящиеся к нему обезличенные логи.
3. Проверить прикладной ответ: HTTP Apache/frontend, доступ к БД без публикации пароля, ответ Zabbix agent согласно его реальной конфигурации.
4. Отдельно согласовать проверку запуска после восстановления. Не останавливать рабочие сервисы ради скриншота.

| Сервис | Установка | Статус | Прикладная проверка |
|---|---|---|---|
| MariaDB | Не проверено | Не проверено | Не выполнена |
| Apache | Не проверено | Не проверено | Не выполнена |
| Zabbix server | Не проверено | Не проверено | Не выполнена |
| Zabbix agent на сервере/клиентах | Не проверено | Не проверено | Не выполнена |

## Критерий приёмки и ограничения

Опубликованы версии, обезличенные конфигурационные выдержки и прикладные результаты каждого используемого сервиса. Running Kubernetes не заменяет проверку приложения. Если пакета нет, кейс для него остаётся запланированным.

Настройка пользователей БД, схемы Zabbix, PHP/frontend, логирования и прав приложений не представлена воспроизводимыми инструкциями исходной версии. Их нужно документировать по реальному стенду, отделяя рекомендации от сделанного.

Формулировка сейчас: «Реализован конфигурируемый запуск установленных Linux services после восстановления состояния; проверка прикладной готовности — следующий этап».
