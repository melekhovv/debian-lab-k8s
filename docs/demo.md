# Демонстрация проекта за 7 минут

[README](../README.md) · [Инженерные решения](decisions.md)

Цель — показать устройство системы, объяснить ограничения и продемонстрировать реальные наблюдения. Не запускать recovery или обновление образа во время собеседования.

## Подготовка заранее

Убедиться, что рабочий каталог содержит правильный локальный конфиг и backup. Запускать существующую лабораторию только штатной процедурой. Проверить доступность всех GUI, состояние сервисов, последние backup и отсутствие секретов на экране. Отдельно сохранить обезличенные результаты, чтобы при недоступности стенда показать проверенные факты с датой, а не обещать live demo.

## Сценарий

| Время | Что показать | Что объяснить |
|---|---|---|
| 0:00–1:00 | Архитектура в README | Четыре контейнерные среды, общая нода и ядро; почему это не четыре VM |
| 1:00–2:00 | Deployment/Service и конфигурация | Закреплённый digest, requests/limits, локальные port-forward; почему не открыт NodePort |
| 2:00–4:00 | Network topology и реальные маршруты | Два прохода через ноду, policy routing, proxy ARP, NOTRACK; ограничения общего счётчика |
| 4:00–5:00 | Сервисы и Zabbix, если реально работают | Разница между Running Pod, процессом и прикладной готовностью; только подтверждённые метрики |
| 5:00–6:00 | Backup-код и проверенные артефакты | Что такое writable layer, whiteouts, пределы согласованности; восстановление не выполнять на рабочем стенде |
| 6:00–7:00 | CI и инженерные решения | Какие регрессии ловит автоматизация, чего она не проверяет и какие улучшения следуют из ограничений |

## Воспроизводимые проверки

Из корня репозитория, Python 3.12+:

```powershell
python -m pip install -r tools/requirements.txt
python tools/validate_repository.py
python -m unittest discover -s tools -p test_validation.py -v
```

Эти команды проверяют файлы и не запускают лабораторию. CI использует Python 3.12; совместимость с другими версиями не обещается без проверки.

Наблюдение существующего кластера без изменения конфигурации:

```powershell
python tools/check_lab.py --context minikube --output lab-observation.json
```

Сборщик не загружает и не исполняет локальный `lab.config.ps1`, не применяет манифесты, не восстанавливает данные и не запускает сервисы. Пишет только новый локальный отчёт, не перезаписывая предыдущий. Context указан явно. Вызовы `kubectl exec` выполняют диагностические команды внутри существующих сред.

Для шести активных TCP-проб добавьте `--probe-routing`. Они создают ограниченный трафик на порт 9 и могут попасть в мониторинг. Ответ TCP RST от закрытого порта считается сетевым ответом; это не проверка приложения. Общий forwarding counter требует независимого подтверждения пути. Просмотрите JSON и удалите чувствительные метаданные перед публикацией.

## Честные ответы на сложные вопросы

- «Почему без PVC?» — текущая реализация сохраняет writable layer. Это учебный компромисс с зависимостью от образа/runtime; миграция на постоянное хранение требует отдельного проекта.
- «Безопасно ли это для production?» — нет: привилегии и GUI рассчитаны на изолированную домашнюю лабораторию. Границы описаны отдельно.
- «Что именно проверяет CI?» — локальные контракты манифестов, ссылки и синтаксис. CI не доказывает готовность Zabbix или recoverability.
- «Что ты реально сделал?» — назвать реализацию и приложенные датированные результаты; не приписывать себе измерения или задачи без доказательств.
