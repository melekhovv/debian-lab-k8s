## Routing: независимое подтверждение пути

| Путь | Ответ TCP:9 | Delta ForwDatagrams | На eth0 сервера |
|---|---|---|---|
| client1 → client2 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |
| client1 → client3 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |
| client2 → client1 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |
| client2 → client3 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |
| client3 → client1 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |
| client3 → client2 | Ответ получен | +2 | Вход TTL 63 → выход TTL 62 |

Счётчики получены первой серией проб. Независимая вторая серия использовала временный Python AF_PACKET observer на серверном `eth0`, EtherType ALL, с фильтром IPv4/TCP, адресами трёх клиентов и destination port 9. Он сохранял только source/destination, TTL и incoming/outgoing, без payload. Для каждого направления зафиксированы вход и выход с уменьшением TTL: [заголовки](2026-11-14-routing-headers.json). Наблюдатель завершился после ограниченного окна; файлы в контейнере не создавал.

Это подтверждает пересылку тестовых пакетов сервером в данной сессии. Это не доказательство невозможности обхода при изменении маршрутов или прав клиентов и не проверка прикладного сервиса на порту 9.

## Zabbix и прикладные проверки

- `zabbix_get -s <учебный-IP-клиента> -k agent.ping` с сервера вернул `1` для каждого из трёх клиентов.
- SQL read-only проверка таблиц history/history_uint за последние 900 секунд на момент наблюдения обнаружила свежие числовые значения: client1 — 10 distinct items, client2 — 7, client3 — 10. Объединение выполнено через items и interface с фильтром трёх учебных IP; значения метрик и учётные данные не публиковались.
- База `zabbix` содержит 203 таблицы; dbversion mandatory/optional — 7000000/7000028. Наличие таблиц само по себе не доказывает целостность БД.
- Apache и nginx внутри сервера вернули HTTP 200 для `/zabbix/`.
- Через локальный port-forward `http://127.0.0.1:13000/zabbix/` вернул HTTP 200 и страницу frontend; клиентские GUI на 3001–3003 вернули HTTP 200 со своими заголовками. Первоначальный 404 на 3000 относился к другому приложению, поэтому ранний GUI-ответ 200 на этом порту не принят как доказательство лаборатории.

Проверка trigger Problem → Resolved, экспорт hosts/templates и доставка уведомлений не выполнялись. Вход в frontend под учётной записью не выполнялся. Получение метрик подтверждено чтением БД и ответами агентов, а не скриншотом dashboard.
